# Agent brief (read this, not docs/02 or docs/03, unless told otherwise)

Rust gpui UI library: `crates/aui` components, `crates/aui-motion` springs/tweens, `crates/aui-tokens` theme, `crates/aui-gallery` renders every design card and the assistant screen (`crates/aui-gallery/src/cards/*.rs`, `assistant/view.rs`, `registry.rs`). Design source: `design/src/cards/<group>/<nn>-<stem>.html`; references: `design/reference/cards/<stem>.png`.

Stack: Rust, gpui-pre 0.3.3 as `gpui` + gpui-kit 0.6 (registry sources under ~/.cargo/registry/src/index.crates.io-*/), macOS only. Prefix shell commands with `export PATH="/opt/homebrew/bin:$HOME/.cargo/bin:$PATH"`. Tools: `cargo run -p aui-gallery` (flags: --theme, --entry, --list, --screenshot <id> <png>, --screenshot-window <png>, --screenshot-delay <ms>, --text-scale), `scripts/parity.sh <entry-id> <reference-stem>` (≤2 % differing pixels is parity for a static card; parity renders open at the display's top-left and occlude the pointer), ImageMagick `compare`/`magick`. When subagents edit the shared tree, build your own work in a `git worktree` with its own CARGO_TARGET_DIR (see memory).

Parity loop for a card you touch: `scripts/parity.sh <entry-id> <reference-stem>` → `target/parity/<stem>.png` + diff + RMSE + differing-pixel %; ≤2 % is parity, and compare with the value in docs/03-parity-process.md's checklist. Design changes: edit design/src, `python3 design/build.py`, re-render the reference with headless Chrome (exact command in docs/03 line ~26), then update the checklist number. Look at PNGs yourself (crop/zoom with `magick`). Pure verification: `cargo build --workspace`, `cargo test -p aui`.

Conventions already decided: no literal colours/sizes/durations in components — `cx.aui().colors`, `aui_tokens::scale::*`, `cx.aui().metrics`, `AuiStyled::{text_role, ui, mono, text_px}` (product text scale 1.1; parity at 1.0); motion only through aui-motion; stateless `RenderOnce` components with lowercase constructors, per-element hover/press state via `aui::util::{interaction_flags, TrackInteraction}`, data in / intents out via closures, no I/O; light and dark both correct; mixed-font inline text via `StyledText::with_runs` (`aui::transcript::prose`, `ansi_runs`, `syntax_runs`); CSS margins collapse only in block flow (rows in a flex column keep both margins); gpui has no letter-spacing, no element transform, and treats `BoxShadow.blur_radius` as sigma (tokens already halve the CSS blur).

gpui gotchas learned the hard way: paint order is background → children → border, so a child at a negative inset is covered by its parent's border (draw rails as a wrapper's border); anything that overflows its box (popovers, fanned stacks) must go through `aui::overlay::popover_layer` or later siblings paint over it; hover tints fade alpha only via `aui_motion::tint_fade` (never tween a colour to `transparent_black()`); collapsed shell rail is 72 px with traffic lights and `AUI_GALLERY_COLLAPSED=1` renders the shell/assistant screens collapsed, `AUI_GALLERY_SCREEN=<Main|Sources|Sheet>` picks which assistant screen `screens/assistant` renders (the `screens/all` page shows all three at once); note cards are one plain hairline box, no accent rails.

`AUI_GALLERY_STEPS` scripts the live assistant mock for a capture — a comma-separated list of the actions and intents the UI would produce (`send:<text>`, `answer:<n>`, `wait:<ms>`, `cmdk`, `cmdb`, `cmdright`, `up`, `down`, `enter`, `esc`, `tab`, `shift-tab`, `approve`, `always`, `deny`, `stop`, `plus`, `shot`), applied after the first frame; pair it with `--screenshot-delay`. Keys are `aui::keys` actions bound in `aui::init`; the grammar and the bindings are in docs/03's "Live behaviour" section.

Backends live outside `aui`: `crates/aui-webview` (a `WebBackend` trait, the scripted `FakeWebBackend` the gallery runs, a `wry` WKWebView behind feature `wry`) and `crates/aui-terminal` (a `TerminalBackend` trait, an OSC 133 `BlockParser`, `FakePty`, plus features `pty` and `tui`) — the traits, the zsh shell-integration snippet and the known limitations (a wry child view paints above gpui; no screenshots yet) are in docs/07-backends.md, and the live gallery entries are `workbench/webview`, `workbench/terminal-live` and `workbench/tui-live`.

Working rules: edit only the files named in your task; build in your own worktree with its own `CARGO_TARGET_DIR` when other agents are active; report in under 200 words (root cause, files, parity before/after, screenshot paths, what you could not verify); never commit.
